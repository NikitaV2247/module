## [0.7.2] — 2026-11-15

Две правки по пожеланию заказчика: убрана нижняя запись в PDF и
добавлены преподаватели (эксперимент: один преподаватель на
дисциплину/занятие).

### Removed

- **Нижняя строка-легенда в недельном PDF** («У группы — не более
  4 пар в день… Пустая ячейка — пара без занятия у группы») удалена:
  страница заканчивается таблицей. Легенды в текстовых карточках
  (пункт 2 меню, `format_generated_week`) и HTML-выгрузке сохранены —

### Added

- **Преподаватели (эксперимент)**. Дисциплина учебного плана получила
  поле `teacher` — ровно один преподаватель (список в JSON отвергается
  с ошибкой «может быть только один преподаватель»):
  - data/curriculum.json — `teacher` у каждой из 8 дисциплин
    (имена вымышленные);
  - data/schedule.json — `teacher` у каждого из 39 занятий;
  - автогенерация (пункт 7, `--generate`) переносит преподавателя
    дисциплины в сгенерированные занятия; `save_schedule` пишет поле
    `teacher` в файл (пустое поле не добавляется);
  - преподаватель виден везде: ячейки PDF («преп. Фамилия И. О.»),
    карточки дня и недели (пункты 1–2 меню), TXT, CSV (колонка
    «Преподаватель»), HTML (одноимённая колонка), iCal (в DESCRIPTION);
  - **проверка конфликтов преподавателя заработала на реальных
    данных**: пункт 6 находит 5 конфликтов в демо-расписании
    (один преподаватель ведёт МДК у нескольких групп одновременно);
    генератор пока не следит за занятостью преподавателя — известное
    ограничение эксперимента;
  - валидация DataLoader: список или не-строка в `teacher` — проблема
    «у занятия может быть только один преподаватель»;
  - `Lesson.teacher_label` — безопасный доступ к полю (повреждённые
    данные не роняют экспорт и отчёт о конфликтах).

### Tests

- 195 тестов (+20): PDF без легенды и с преподавателем (pdftotext),
  загрузка/сохранение teacher, отказ от списка преподавателей,

## [0.7.0] — 2026-11-12

Расписание звонков — по дням недели (по файлу zvonki.pdf учебной части);
в субботу — максимум 4 пары; пары дня — подряд, без «окон». Эксперимент
с пунктом меню «PDF автогенерации» из черновой ветки 0.7.0 откатан —
релиз собран от версии 0.6.0.

### Added

- **Секция `bell_schedule` в data/curriculum.json**: расписание звонков
  по дням недели из файла zvonki.pdf — пн — 6 пар, вт–пт — 7, сб — 4.
  Время пары обозначено как «начало–конец» пары целиком (пары «1»…«6/7»);
  слот «Разговоры о важном» (пн 12:00–12:30) парой не является и в сетке,
  как и в самом расписании, не фигурирует.
- **Дневные сетки в моделях (src/models.py)**: `BELL_BY_DAY` — встроенная
  сетка по дням, `slots_for(day)`, `day_pair_count(day)`;
  `time_slot(number, day)` и `break_after(number, day)` принимают день
  недели (без него — общая сетка вт–пт, как раньше). `Lesson.time`
  подставляет время по сетке именно того дня, на который занятие
  приходится: 3-я пара в понедельник — 12:40–14:15, в субботу —
  11:45–13:20. `apply_bell_schedule()` подменяет сетку значениями
  из учебного плана.
- **CurriculumLoader читает `bell_schedule`**: при загрузке учебного
  плана сетка переопределяется из JSON (неизвестный день, неверный
  формат времени, непоследовательные номера пар — ValueError);
  сетка сохраняется в `Curriculum.bell_by_day`. Раздел отсутствует —
  работает встроенная сетка.
- **Валидация «окон»**: DataLoader.validate и
  conflicts.check_constraints сообщают о промежутках между парами
  группы в учебном дне (вид нарушения `window`); проверка сетки
  звонков стала дневной — пара 5-я в субботу теперь «вне сетки дня».
- Тесты: дневные сетки и время пар по дням, парсер `bell_schedule`
  (корректный, без секции, с ошибками), генерация 16 недель без
  нарушений (суббота ≤ 4 пары, окна отсутствуют), валидация окон.

### Changed

- **Генератор соблюдает сетку своего дня (src/scheduler.py)**:
  слоты-кандидаты ограничены сеткой звонков дня — в субботу пары
  выше 4-й не появляются в принципе (раньше при занятых кабинетах
  занятие «сползало» на 5-ю пару субботы).
- **Пары группы в дне идут подряд**: новая пара ставится только
  вплотную к уже стоящему блоку группы (перед ним или после него) —
  «окна» вида «3-я и 5-я без 4-й» генератором не создаются.
- **Пример data/schedule.json приведён к правилам**: закрыты «окна»
  (пн: 4-1П9 1-2-3-5 → 2-3-4-5, 4-2П9 1-2-3-6 → 3-4-5-6;
  чт: 4-2П9 1-2-4 → 1-2-3) — кабинеты перенесены без конфликтов.
- Вывод недель (консоль, TXT, HTML, PDF) и легенды указывают дневную
  сетку (пн — 6, вт–пт — 7, сб — 4) и правило «без окон»; в PDF недели
  время пары выносится в ячейку дня (в подписи строки фиксированного
  времени больше нет — у каждого дня оно своё).
- `ScheduleGenerator.time_slots(day)` возвращает сетку конкретного дня.

## [0.6.0] — 2026-11-12

Меню упрощено по пожеланию заказчика: пункты 7 и 8 объединены.

### Changed

- **Пункт 8 меню удалён**, его функция объединена с пунктом 7:
  «автогенерация недели всех групп из учебного плана (с записью в
  schedule.json)» — вводится только неделя, группа больше не запрашивается.
  Расстановка привязана к номеру недели семестра (seed): у каждой недели
  своё расписание, повторный запуск той же недели даёт тот же результат.
  Расписание в памяти меню перечитывается после генерации.
- **run_generate (src/main.py)**: параметр `seed_by_week` (используется
  пунктом 7 меню); неделя без явного указания берётся из дат
  data/schedule.json, а не с сегодняшней даты (CLI `--generate` без `--week`
  теперь пересобирает неделю, которая лежит в расписании; при нечитаемом
  расписании — сегодняшняя, как раньше). Поддержка одного дня (`--day`)
  осталась в командной строке.
- Тесты: пункт 7 меню (39 занятий для всех групп, запись файла, пункта 8
  нет), неделя по умолчанию из расписания, seed_by_week (стабильность
  одной недели, различие разных недель).

## [0.5.0] — 2026-11-12

Автогенерация недели группы теперь строится из учебного плана и записывается
в data/schedule.json — по замечанию заказчика: пункт 7 выдавал одну и ту же
расстановку и ничего не сохранял.

### Added

- **run_auto_week (src/main.py)**: автогенерация недели одной группы
  из учебного плана (curriculum.json — предметы, часы, кабинеты) с записью
  в schedule.json: занятия группы заменяются, подпись недели и даты дней
  обновляются, остальные группы остаются без изменений. Неделя выбирается
  по номеру/дате или берётся из дат текущего расписания.
- **Пункт 7 интерактивного меню** — «автогенерация недели группы из учебного
  плана (с записью в schedule.json)»: запрашивает группу и неделю, печатает
  расписание и подтверждение сохранения, обновляет расписание в памяти.
- **`--auto-schedule --week НОМЕР|ДАТА`** и `--out`: выбор недели семестра
  и файла сохранения из командной строки.
- **Seed у WeekScheduler (src/scheduler.py)**: параметр seed делает
  расстановку зависимой от номера недели — у каждой недели семестра
  своё расписание, повторный запуск той же недели даёт тот же результат
  (seed=None — прежний детерминированный режим).
- Тесты: вариативность и стабильность seed, генерация с seed на все недели,
  run_auto_week (состав из учебного плана, запись файла, нетронутые
  остальные группы, ошибки группы/недели).

### Changed

- `--week` с номером/датой теперь работает и с `--auto-schedule`
  (раньше — только с `--generate`).
- test_to_week_html_page берёт даты дней из data/schedule.json вместо
  зашитой ноябрьской недели — тест больше не зависит от содержимого данных.

## [0.4.0] — 2026-11-10

Период семестра и распределение пар по дням — по замечаниям заказчика:
расписание можно собрать на **любую неделю с 2 сентября по 20 декабря
2026 г.** или на отдельный день, а пары в неделе концентрируются
по 3–4 в день — вместо «по 2 пары каждый день».

### Added

- **Модуль `src/semester.py`**: период семестра 02.09–20.12.2026
  (16 недель); выбор недели по номеру (`--week 1` — 1-я неделя
  сентября) или по дате (`--week 2026-11-23` — 4-я неделя ноября),
  отдельный день по дате (`--day 2026-10-08`); воскресенье — выходной.
- **Учебный план с периодом**: `curriculum.json` хранит даты начала
  и конца семестра; 1-я неделя начинается со среды 2 сентября,
  поэтому занятия в ней — только ср–сб.
- Подписи недель («2–5 сентября 2026 г. · 1-я неделя семестра»)
  и дней («Четверг, 8 октября 2026 г.») — в данных, консоли и экспортах.
- В просмотровых командах день можно указывать датой:
  `--group 4-1П9 --day 2026-11-10` → вторник.

### Changed

- **Дни с 3–4 парами**: генератор заранее считает дневные лимиты —
  13 пар недели распределяются как 4 + 3 + 3 + 3 (пн–чт), а не
  по 2 пары во все шесть дней; пятница и суббота свободны.
- Пересчёт часов при семестре 16 недель: 80 часов → 3 пары в неделю
  (МДК 01.03), итого у группы 13 пар вместо 12.
- Даты дней недели и заголовок недели в data/schedule.json теперь
  берутся из выбранной недели семестра, а не зашиты в учебном плане.

### Fixed

- Жадное заполнение «дни подряд» заводило генератор в тупой перебор
  на нагрузке 6 дисциплин × 4 пары; теперь внутри разрешённых дней
  кандидаты упорядочиваются по загрузке дня — backtracking не нужен.

Тесты: **131 passed** (было 105), покрытие — **88%**.

## [0.3.0] — 2026-11-10

Сокращение объёма данных по заданию заказчика: в проекте остаются
**3 группы** (4-1П9, 4-2П9, 3-1П11) с фиксированным учебным планом,
а расписание собирается генератором из плана, а не парсится из docx.

### Added

- **Учебный план** `data/curriculum.json`: 3 группы, 8 дисциплин
  с часами на семестр и списками кабинетов; семестр — 18 недель.
- Команда **`--generate`**: собирает неделю всего колледжа из плана
  (3 группы × 12 пар = 36 занятий) и сохраняет в `data/schedule.json`.
- Пересчёт **часов в пары**: 1 пара = 2 ак. часа; 40 часов → 1 пара
  в неделю, 68–80 часов → 2 пары (12 пар в неделю у группы).
- **Кабинеты-альтернативы**: если кабинет занят другой группой,
  дисциплина ставится в следующий по списку (МДК 01.02: 408 → 412 →
  405 → 406); спортзал — обычный кабинет, конфликт в нём проверяется.
- Проверка ограничения «**не больше 4 пар в день**» в валидаторе
  данных и в отчёте конфликтов (вид нарушения `load`).

### Changed

- Сетка звонков расширена с 4 до **7 пар** (до 19:15–20:50): по времени
  пары могут стоять вплоть до 7-й, при этом у группы — не более 4 пар
  в день (ограничение задания).
- Генератор распределяет пары **равномерно по дням** (наименее
  загруженные дни первыми) — вместо compact-заполнения начала недели.
- `abbreviations.py` сокращён до словаря кратких имён дисциплин
  (МДК → «МДК 02.02»); CSV хранит полные наименования.
- PDF недели: строки таблицы — с 1-й пары по последнюю занятую.

### Removed

- Данные 35 групп колледжа (649 занятий) и словарь из 100+ расшифровок
  сокращений исходных docx-файлов.

Тесты: **105 passed**, покрытие — **86%**.

- iCal: в описании события — группа и номер пары; PDF: единая сетка,

- Покрытие тестами выросло до **85%** (81 тест), добавлены тесты CLI.

### Removed

- Половины пар по 45 минут и внутренние перерывы внутри пары.
- Внеучебные мероприятия («Разговоры о важном») и таймлайн дня
  (`day_grid`, `DAY_EVENTS`, `GridItem`).
- Колонка «Половины» в CSV и HTML.

Проект стал меньше на ~660 строк кода.

## [0.1.0] — 2026-11-04

Первый релиз учебного проекта (МДК 02.02, Костромской политехнический колледж).

### Added

- Загрузка расписания колледжа из JSON: 35 групп, 711 занятий, 6 дней.
- Расписание звонков по дням недели (`TimeSlot`, `BELL_SCHEDULE`):

- Система перемен: перерыв 5 минут внутри пары (кроме 1-й пары пн–пт)
  и перемены между парами с «Разговорами о важном» в понедельник.
- Запросы: карточка дня, неделя с переменами и «окнами», сводная доска
  дня, поиск по предмету с расшифровкой сокращений.
- Генерация расписания на неделю с учётом времени пар; автогенерация
  алгоритмом «жадный порядок + backtracking» (`WeekScheduler`).
- Проверка конфликтов (группа / аудитория / преподаватель-при-данных)
  и учебных ограничений (временная сетка дня).
- Экспорт: TXT, CSV, HTML (день и неделя), iCal (.ics), PDF (неделя, A4).
- Инфраструктура: CI (GitHub Actions: линтеры, тесты, покрытие, дымовой
  прогон), Branch Protection для `main`, pre-commit, шаблоны PR и Issue,
  Kanban с колонками Backlog/Ready/In Progress/Code Review/QA/Done.
- 78 unit-тестов, покрытие 78%; шрифты DejaVu в комплекте.

### Fixed

- D-01 (critical): сборка HTML-таблицы — вложенные `<table>` из-за
  приоритета конкатенации (регресс-тест `test_to_html_single_table`).
- D-02 (major): псевдо-аудитории «ср»/«экс» считались кабинетами
  в проверке конфликтов.
- D-03 (major): зависание планировщика на невыполнимой нагрузке —
  добавлены предпроверка и бюджет перебора.
- D-04 (minor): невалидное свойство X-SKIPPED-NO-TIME после
  END:VCALENDAR в iCal.

### Known limitations

- Преподаватели, вместимость и оборудование аудиторий отсутствуют
  в данных источника — соответствующие проверки не наполняются.
- Две пары исходных файлов вне сетки звонков (Сб 5-я у 2-1П9,
  Пн 7-я у 1-1С11) подсвечиваются валидатором и пропускаются
  при экспортах.
- Автогенерация выполняется по одной группе; глобальная координация
  аудиторий между группами запланирована после v0.1.0.
